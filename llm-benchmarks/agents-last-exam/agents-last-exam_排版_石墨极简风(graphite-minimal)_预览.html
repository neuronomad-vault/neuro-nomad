AGENTS’ LAST EXAM · ALE

122 个活跃任务 · 55 个子行业 · 隐藏参考 · 15 个配置

ALE（Agents’ Last Exam，UC Berkeley RDI × RDI Foundation 主导，论文 v1 于 2026-06-03 上线 arXiv）不考「模型能否答对难题」，而是把完整的 Agent 系统（harness + 基础模型 + 工具环境）放进带真实专业软件的 Windows / Linux 沙箱，只给一句任务描述，让它跑到完成，再对留下的交付物用隐藏参考 + 确定性 grader 判分。

现行 v1.1 含 122 个活跃任务，覆盖按 O*NET / SOC 2018 组织的 55 个子行业 / 13 个产业群；官方榜 2026-11-05 更新的头名 Pass Rate 为 45.9%（ALE-Claw / Gemini 4 Carbon），远未饱和。

01

WHAT IS ALE

一句话定义

ALE 的核心不是「更难」，而是换评测对象：从模型输出的答案，换成完整 Agent 系统在真实工作环境里留下的交付物。每道题由行业专家把本人做过的项目改写成可核验评测，Agent 在装有实际专业软件的沙箱里产出文件、图表、代码或配置，grader 对照隐藏参考给出 0–1 分。

这意味着同一模型换 harness、换 effort、换工具环境，分数会明显变化；官方榜每行因此是 Harness / Model / Effort 三元组，而不是裸模型排名。

核验说明：一手资料归档于 sources/agents-last-exam/，抓取与核验日期 2026-11-06。官网、官方 v1.1 / v1.0 两个榜单页、arXiv 摘要页、官方 GitHub 仓库与官方文档站均直连可达并逐页核对；两份榜单 CSV 为人工转录（官网未提供结构化下载端点）。Hugging Face 官方域名本次直连全部失败（HTTP 000），数据集卡片正文与元信息未取到，其存在与用途由官方博客、GitHub README 与 docs/releases/v1.1.md 交叉确认。

路径与日期约定：正文反引号中的 ale_run/、docs/releases/…、selected_tasks/…、releases/v1.1/assets.json 一律指官方仓库 rdi-berkeley/agents-last-exam 内的路径；本仓库路径统一写作 sources/…、benchmarks/…。README 索引的「提出时间」取论文 v1 首发日 2026-06-03；官方博客公告 2026-06-14、仓库首个 Initial public release commit 2026-06-05 是另外两个事件，不与论文首发日混用。

CAVEAT · 命名警示

命名警示（两个坑）：① 缩写 ALE 与 ALE-Bench 在二手平台上被混用——BenchLM 把 ALE 的官方榜镜像条目命名为 alebench，而 Sakana AI × AtCoder 另有一个完全无关的 ALE-Bench（ALgorithm Engineering Benchmark，AtCoder Heuristic Contest 优化题，arXiv:2506.09050，NeurIPS 2025 D&B）；② BenchLM 站内对同一个 ALE 建了两个口径互斥的条目（agentslastexam 厂商自报 / alebench 官方榜镜像）。逐项辨析见「附：命名与口径辨析」。

官方同时维护 v1.0（legacy） 与 v1.1（current） 两个榜单，但按 AGENTS.md §2.1 逐条比对，两者差异属于「题量增减 + 题目刷新」：任务形态仍是 GUI + CLI 沙箱交付物、判定仍是 hidden reference + grader、计分仍是 Pass Rate / Score 双指标、构念仍是长程经济价值专业工作，官方也把滚动换题作为 ALE 的整体设计而非版本分界。五项判据中无可确认成立的两项，故不拆成两个文档，改在第 2.4 节作沿革注记，并在口径警示块中写明 v1.0 与 v1.1 分数不可比。

2.2 任务形态与运行环境

每道题是一个真实职业工作流，由行业专家把本人完成过的项目改写成可核验的评测：给定 instruction 与真实输入文件，Agent 在装有实际专业软件的沙箱里产出交付物，grader 对照隐藏参考给 0–1 分。官方示例包括：把 SEC 10-K 报表解析成结构化财务 schema、用 Longstaff–Schwartz 回归实现美式期权定价基准、从原理图生成布好线的 KiCad PCB、跑全基因组变异检测并输出 VCF、在 Kubernetes 集群里定位支付 API 故障根因、按司法辖区规则从账单登记簿计算律师费、用 TCGA-LUAD 数据做 KRAS 分层生存分析。

不少任务需要商业软件（Adobe After Effects、Siemens NX、Unreal Engine、Moldex3D、Rhino 3D、FSLeyes 等）或受限数据，因此官方榜把任务按许可证分成 Full（含 license-gated 任务）与 Unlicensed（只保留用自由工具即可复现的子集）两种视图——这是同一版本内部的另一层口径，跨视图排序同样不能混用。v1.1 把 6 个原本依赖商业软件的任务改造成开源 Linux 工作流（Blender、FreeCAD、LinuxCNC / CAMotics、Kratos、MuseScore、Ardour），并移除 engineering/mold-flow（无经验证的开源替代）。

2.3 滚动评估与公开 / 私有边界

ALE 采用 rolling evaluation：约每 6 个月发布一批新的公开任务实例，私有任务轮换进公开池、退役的公开任务轮换出去，held-out 私有任务用于官方计分，以降低针对固定公开测试集训练的价值。公开题集只是总语料库的子集；依赖私有数据、商业许可软件或保留评估材料的题目始终留在私有池。这意味着任何「ALE 分数」都必须绑定题集版本与 split，否则无法复现。

另有 ALE-CLI：CLI-only 子集（v1.0 legacy 榜中标注 linux task only），覆盖 40 / 55 个子行业，供只在终端里工作的 Agent 使用。官方 2026-06-14 博客称其当时最好 Agent 通过率 25.2%，并对比 Terminal-Bench 82.0%、SWE-bench-Pro 59.1%——这是子集分数，与全量 ALE 榜不可比。

2.4 v1.0 → v1.1 沿革

docs/releases/v1.1.md 给出的精确变更：v1.1 从 152 题（官方榜口径）中退役 30 题、保留 122 题；其中 57 题需重跑、65 题结果可保留。按变更类型计数（可重叠）：Instruction 47 题、Verification 43 题、Environment 32 题、Data 23 题。CPU 覆盖提升到 119 题，另 3 题为 GPU 任务（列于 selected_tasks/gpu.txt）。

评测方式

3.1 一次运行的六个阶段

ALE 把一次运行拆成准备、执行、判分、汇总四个阶段、六个动作。隐藏参考只在 Agent 运行结束后才 stage 进沙箱，避免答案泄漏；ale_run 把每次运行规范化成统一 trajectory，连同原始日志、事件流、评分与产物一并留档，可完整回放审计。

3.2 两个指标


 Pass Rate

run 拿到满分的任务占比（严格成功）。现行榜定义为「the share of runs that earned a perfect score」。


 Score

所有任务的平均部分得分，允许部分完成也拿分。


 缺失与失败

两者都按所选任务集全部题目求平均；缺失结果与失败 run 一律记 0。超时的 run 保留已判分数。


 效率数据

官网榜同时给出 Total Runtime（各题 Agent 执行时间之和，不含环境准备与评测）、Output Tokens；v1.0 legacy 榜另给 Est. Cost、Input / Output Tokens，并有 Full / Unlicensed 许可视图与效率前沿图。


 判分措辞不一致

Snorkel 的 v1.1 方法页写「deterministic graders, not LLM-as-a-judge」，而官方 Docs 写「Deterministic and judge-based graders」——两处措辞不一致，按 §5 并列保留，本文不替官方消解。

3.3 评测对象是 model + harness 系统

官方反复强调 ALE 评的是「harness + 基础模型 + 工具 + 记忆 + 上下文管理 + 行动循环 + CLI/GUI 接口」组成的完整配置，不是裸模型。同一模型换 harness 或 effort 档位，分数会明显变化；官方榜每行是 Harness / Model / Effort 三元组，且默认展示该配对在全部任务上的最强 effort。Snorkel 的 v1.1 页注明官方参考 harness 为 Claude Code CLI 与仓库内置的 OpenClaw，榜单另收 Codex、Kimi Code、Muse Code、ZCode 与 ALE-Claw 等。

05

KNOWN PITFALLS

已知缺陷与口径陷阱

CAVEAT · 口径提示

不要跨口径比较：本节出现的 45.9%、38.2%、60.0%、25.2%、2.6% 等数字分别来自 v1.1 官方榜、v1.0 legacy 榜、BenchLM 自报榜、厂商发布日志与官方博客的不同题集版本与 split，仅用于说明口径差异，不得拼接成时间序列或排名。


 01 版本与 split 是最大的坑

v1.0（152 题）/ v1.1（122 题）分数不可比；同一版本内还有 Overall / ALE-CLI / Near-term / Full-Spectrum / Last-Exam 五种 split 与 Full / Unlicensed 两种许可视图。滚动评估每约 6 个月换一批题，连「v1.1」本身也随任务修订持续刷新（Results updated 与 Benchmark reference 日期不同）。


 02 官方自己给出的题量与专家数不一致

公开题集 147（Snorkel）vs 152（官方 legacy 榜 / LLMLearner），语料库 1,000+（论文 v4 / Docs）vs 1,500+（官网首页 / 博客），专家 250+（论文 / Docs）vs 300+（官网 / Snorkel / 博客），机构 44（Snorkel）vs 100+（博客）。本文按 §5 全部并列，未替官方统一。


 03 Best per task 不是 Agent 成绩

legacy 榜首行 56.6% 是「每题取全局最好一次运行」的聚合上界，把它当作某个模型的历史最高分会高估约 18 个百分点。


 04 Pass Rate 与 Score 混用会严重误读

现行榜 Score 普遍高出 Pass Rate 25–35 个百分点；论文 v4 摘要称最难 tier「平均 full pass rate 低于 1%」，而博客称该 tier 最好 Agent 2.6%（另有 0% 表述）。「通过率」与「部分得分」是两把尺子。


 05 测的是完整系统，且默认只展示最优 effort

每行是 harness + model + effort 三元组，官方默认显示该配对在全部任务上的最强档；跨行比较同时混入 CLI 版本、工具循环、记忆与推理档位差异。第 15 行 Off 档 5.7% 说明 effort 影响可能远大于模型差异。


 06 独立复现门槛高、成本高

官方榜的 Total Runtime 普遍 60–180 小时，legacy 榜 Est. Cost 单配置可达 $1,340–$4,340；部分任务需商业 CAD / EDA 软件、受限数据或 GPU，v1.1 把 6 题改成开源流程后仍有 3 题需 GPU。官方不分发预构建镜像，需按 releases/v1.1/assets.json 拉固定镜像与数据 pin，并在 Ubuntu / Debian 主机上跑 env/verify_host_env.sh。


 07 二手平台把同一个 ALE 拆成两个条目，且其中一个已过期

BenchLM agentslastexam（20 行全自报，计入 Agentic 综合分）与 alebench（v1.0 官方榜镜像，display only）并列存在；LLMLearner / DataLearner 又各自把官方榜行与厂商自报行混在同一张榜里（LLMLearner 标注 34 行中 28 行独立测量、6 行仅厂商自报，榜首 43.2 即自报）。三家都未以 v1.1 为准。详见附录。


 08 缩写撞名可能引向完全不同的基准

ALE-Bench 在 Sakana AI 语境下指 AtCoder 启发式优化竞赛基准（40 题，分数制、可迭代改进），与 ALE 的「专业工作流交付物」构念、题量、判分方式都不同，分数毫无可比性。

07

HOW TO READ THE SCORE

结论

ALE 把评测对象从「模型的答案」换成了「Agent 在真实工作环境中留下的交付物」：55 个子行业的真实软件与输入、CLI + GUI 双通道沙箱、运行结束后才注入的隐藏参考、可回放的统一 trajectory，这套约束比闭卷题集更难靠记忆或提示工程绕过，也让 Pass Rate 与 Score 的 25–35 个百分点落差成为有信息量的诊断——今天的 Agent 能推进大量工作，却仍难以可靠地端到端交付。

但它目前不是一个可以直接读数的稳定榜单。官方同时挂着 v1.0 legacy 与 v1.1 两代题集、五种 split、两种许可视图，题量与专家数在不同页面自相矛盾，滚动评估持续换题；三个聚合平台又各自把官方榜与厂商自报混排，BenchLM 甚至为同一基准建了两个口径互斥的条目，其中一个还停留在已标 legacy 的 v1.0。

引用任何「ALE 分数」时，必须同时给出题集版本、Results updated 日期、split、许可视图、harness、模型与 effort，并确认它来自官方榜还是厂商自报；否则 41.8% 与 60.0% 这样的差异会被误读成模型能力差距。

「先写题集版本与日期，再写 split 与许可视图，最后写 harness、模型与 effort。」
